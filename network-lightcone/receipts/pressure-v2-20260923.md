# Network Lightcone pressure test v2: Neighbor Discovery semantics

This is an isolated synthetic raw-Ethernet replay against the standalone
network Lightcone. No frames were transmitted. No host policy or packet
enforcement participated. The authored world and local diagnostic pack were
not changed or sealed; only the structural observer was corrected.

The challenge generator at `network-replay/experiments/pressure_v2.py`
declared 31 expectations before replay. It included six valid Neighbor
Discovery controls, 15 invalid Neighbor Discovery cases, five IPv6 extension
cases, and five IPv4/transport controls. The original manifest and PCAP remain
under `artifacts/experiments/pressure-v2-20260923/`.

## Findings and correction

The baseline replay matched 19/31 expectations. Twelve Neighbor Discovery
messages with otherwise valid checksums and hop limits incorrectly admitted
causal context. The missing checks were multicast targets, zero-length or
truncated options, unspecified-source restrictions, a non-link-local Router
Advertisement source, and a solicited Neighbor Advertisement sent to a
multicast destination.

The observer now checks those [RFC 4861](https://www.rfc-editor.org/rfc/rfc4861.html)
conditions before emitting any NDP seed. The same immutable challenge then
matched 31/31 expectations: 20 frames had zero seeds and empty neighborhoods,
and 11 admitted context. All six valid Neighbor Discovery controls still
admitted context. A deterministic 20,000-input wire-parser stress test passed
its no-panic and malformed/unknown-zero-seeds assertions. This stress test is
not proof of complete parser safety or semantic coverage.

| Baseline false-admission case | Corrected observer reason |
| --- | --- |
| `ns-multicast-target` | `ndp_multicast_target` |
| `ns-zero-length-option` | `ndp_option_length_invalid` |
| `ns-truncated-option` | `ndp_option_length_invalid` |
| `ns-unspecified-source-unicast-destination` | `ndp_unspecified_source_destination_invalid` |
| `ns-unspecified-source-with-link-option` | `ndp_unspecified_source_link_option` |
| `ra-global-source` | `ndp_router_source_not_link_local` |
| `ra-zero-length-option` | `ndp_option_length_invalid` |
| `rs-unspecified-source-with-link-option` | `ndp_unspecified_source_link_option` |
| `rs-zero-length-option` | `ndp_option_length_invalid` |
| `na-multicast-target` | `ndp_multicast_target` |
| `na-solicited-to-multicast` | `ndp_solicited_multicast_advertisement` |
| `na-zero-length-option` | `ndp_option_length_invalid` |

The previous 27-frame adversarial replay was rerun against this observer: it
still matched 25/27 expectations. The outstanding failures remain a valid DNS
query without a direct DNS seed and a valid VLAN-tagged frame with no context.
Those gaps are explicitly listed in the coverage ledger.

To rerun the corrected evaluation from a fresh checkout, generate the corpus
with `python3 network-replay/experiments/pressure_v2.py --out <new-corpus>`,
run `cargo run -p network-lightcone-replay --offline -- --input
<new-corpus>/frames.pcap --out <new-replay>`, then compare with
`python3 network-replay/experiments/evaluate_adversarial_v1.py --manifest
<new-corpus>/manifest.json --replay <new-replay> --out <new-results>`.

Verification included `cargo test --workspace --offline`, the two frozen
raw-frame challenge replays, `network-lightcone/tools/verify.py`, and the
existing 20-case structural challenge. The world validator still reports
`local_diagnostic` and `sealed=false`.

This closes twelve measured false admissions. It does not imply that any
valid-shaped IPv6 probe sharing represented causal structure is excluded, that
all IPv6 or Neighbor Discovery semantics are parsed, or that network attacks
have been prevented. The Lightcone remains passive and unsealed.
